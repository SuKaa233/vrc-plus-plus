# VRC++ 功能完善路线

> 最后更新：2026-08-15  
> 原则：先补高频只读能力和国内线路稳定性，再做历史统计与上游写操作。实际完成度仍以 [实现状态批注](implementation-status.md) 为准。

## 当前基线

已经具备登录/2FA/会话恢复、好友与用户详情、世界搜索、共同好友关系网、Pipeline/SSE、SQLite 离线快照、图片缓存、代理配置和深浅主题。当前主要缺口不是页面数量，而是搜索、整理、诊断、历史和桌面交付尚未形成闭环。

## 优先级

| 优先级 | 方向 | 价值与原因 |
|---|---|---|
| P0 | 好友整理与统一搜索 | 数百好友后，单纯列表和图谱不够用 |
| P0 | 网络诊断与缓存管理 | 中国线路下需要准确区分 REST、Pipeline、图片、代理故障 |
| P0 | 关系网持续使用 | 保存布局、圈层筛选、仅刷新过期节点，减少重复请求 |
| P1 | 世界与实例闭环 | 从发现走到实例查看、安全链接和启动加入 |
| P1 | 本地历史与常遇好友 | 形成区别于普通在线列表的长期价值 |
| P1 | 通知、邀请与群组 | 有价值但包含写操作，应在只读能力稳定后实施 |
| P2 | 托盘、安装和双源更新 | 决定能否长期日用，但不早于数据层稳定性 |

## 迭代 A：日常好友工作台

### 统一搜索

> **实现批注（2026-08-15）：🟡 主体完成。** 顶部统一入口已支持本地好友、备注、分组、标签、世界快照，以及 `usr_` / `wrld_` ID 和对应链接解析。普通文本只查本机数据，不增加上游请求；instance location 与结果更新时间展示待补。

- 一个输入框识别好友名称、用户/世界 ID、VRChat 链接和 instance location；
- 普通文本输入做 400–600ms 防抖；
- 结果显示来源和更新时间，离线时继续搜索最后一次快照。

### 本地备注、标签和分组

> **实现批注（2026-08-15）：🟡 主体完成。** 好友详情已可编辑本机备注、分组、颜色和多个标签，SQLite 按账号数据目录持久化，列表和统一搜索已联动；关系网标签筛选、加密导出待补。

- 好友可添加本地备注、颜色和多个标签；
- 好友列表与关系网共用标签筛选；
- 明确区分 VRChat 备注与本机备注；
- 支持加密备份，Cookie 永不进入备份。

### 好友列表效率

- 按在线、名称、平台、最近活动和标签排序；
- 只看可加入、私密、离线或指定平台；
- 使用虚拟列表，数百好友时不一次渲染全部卡片；
- 保留滚动位置、筛选条件和最近打开的资料。

验收：187 位好友的本地搜索更新时间低于 100ms；备注重启后存在；无匹配筛选绝不退化为显示全部。

## 迭代 B：关系网增强

### 布局持久化

> **实现批注（2026-08-15）：🟡 主体完成。** 节点位置、缩放和平移已按当前账号保存到浏览器本机存储，含布局版本；拖动和视口变化会防抖保存。新增节点的增量空位布局和版本迁移待补。

- 按账号保存节点位置、缩放和平移；
- 好友增删时保留旧节点，只给新节点寻找空位；
- 提供恢复自动布局和仅重排当前圈层；
- 布局版本化，算法升级时可迁移或重置。

### 圈层与增量扫描

> **实现批注（2026-08-15，关系网第三版）**：🟢 已完成默认隐藏孤立点、核心圈筛选、手动添加指定好友、手动选择后扫描、批次人数预告、扫描后差量统计、全屏画布和拖动性能拆分。扫描前可以准确说明将请求多少位好友，但无法在上游返回前准确预测会新增多少条连线，因此界面明确区分“本次观察人数”和“结果连线数”。下一阶段可继续做圈层命名、按本地标签筛选和社区折叠。

> **实现批注（2026-08-15）：🟡 增量扫描完成。** 默认只选未扫描或扫描时间超过 7 天的好友，优先未扫描、在线和最旧数据；有效期内不会回退为全量请求。社区发现、预计请求数和 429 冷却展示待补。

- 先做连通分量，再做本地社区发现；
- 支持只看某圈层、跨圈连接和高连接节点；
- 默认只扫描未扫描或超过 7 天的节点；
- 显示预计请求数、上次时间、缓存命中和 429 冷却时间；
- 不做无人值守全量循环扫描。

验收：300 节点、1000 条边下拖动流畅；默认头像重叠为 0；重启后位置误差小于 1px；有效期内节点不重复请求。

## 迭代 C：国内线路诊断与缓存中心

### 分层诊断

> **实现批注（2026-08-15）：🟡 第一版完成。** 设置页已分别展示数据库、REST 探针、登录态、Pipeline、当前网络模式和媒体缓存，不再用单一红灯概括；DNS/TLS/系统时间与 CDN 独立主动探针待补。

分别展示 DNS/TLS/系统时间、REST、登录会话、Pipeline、图片 CDN、本机缓存和代理连通性。结论使用“REST 可用、Pipeline 受限、图片走缓存”，不用单个红灯概括全部问题。

### 缓存与 API 仪表盘

> **实现批注（2026-08-15）：🟡 第一版完成。** 已展示数据库大小、实体快照条目/字节数、媒体文件/字节数和本机备注数量；可明确确认后仅清理媒体文件，不删除数据库、会话、备注和关系图。LRU、容量上限、请求统计与脱敏诊断包待补。

- 显示数据库、图片和日志占用；
- 图片 LRU、容量上限与按资源清理；
- 最近 24 小时请求数、缓存命中率、403、429、平均延迟和 Pipeline 重连；
- 一键生成可预览、自动脱敏的诊断包。

验收：断网时继续展示快照；用户能判断故障层级；诊断包自动测试不含 Cookie、Authorization、Pipeline token、邮箱和私密 nonce。

## 迭代 D：世界与实例闭环

> **实现批注（2026-08-15）：🟡 第二版完成。** 世界详情现已展示上游返回的公开实例摘要（人数、区域、类型），点击后才读取完整实例，避免一次性请求风暴；本机收藏与 VRChat 上游收藏明确分区，收藏分组来自账号；可逐人确认发送邀请。完整实例成员列表仍待补。

- 世界详情抽屉：作者、标签、容量、热度、更新时间和本地备注；
- 区分 VRChat 收藏与本地收藏；
- 可见实例列表、区域、人数、权限和当前好友；
- 复制官方链接、instance location、启动 VRChat 加入；
- 私密实例 nonce 复制前警告，历史默认只保留世界 ID；
- 世界更新提醒使用长 TTL 和分散刷新。

所有启动、邀请等动作必须由用户点击；失败时区分权限、实例已满和数据过期。

所有结论标注“基于本机观测”，数据不足时不输出看似精确的排名。

1. 统一搜索 + 本地备注/标签；

4. 世界/实例闭环；

## 不进入路线的能力

- 公共代理池、自动换 IP；
- 集中托管账号或 Cookie；
- Photon、客户端注入和进程内操作；
- 公共用户/世界全量抓取；
- 自动批量加好友、群发邀请或自动值守账号；
- 未经确认上传好友关系、活动历史和私密实例信息。

## 第二批完成后的下一轮候选

1. **群组事件日历**：将公开公告中的时间信息与 VRChat Group Calendar 独立读取并展示，按群组订阅本机提醒；不自动报名或代表用户加入实例。
2. **世界回忆补全**：后台低频回填历史中的世界名称与封面，增加同行好友、到访天数和收藏变化；仍不保留私密 instance nonce。
3. **头像整理增强**：本机收藏夹、最近使用来源、标签批量编辑和失效收藏提示；不下载模型资源。
4. **缓存容量治理**：媒体 LRU、容量上限、按资源类型清理、缓存命中率与失败回退统计。
5. **脱敏诊断包**：用户预览后导出线路、状态码、延迟与缓存信息，自动排除 Cookie、Authorization、邮箱和私密位置。

4. **群组日历只读接入**：读取已加入群组的可见事件，为今晚罗盘和好友动向提供公开活动背景；先不实现创建、修改和报名。

验收：每条建议可以回到好友、世界、朋友圈或历史明细；断网时使用带时间戳的缓存；一次刷新不额外形成按好友全量请求。

### 好友动向下一批候选

1. ⬜ **好友聚焦回放**：选择一位好友后，只显示其上线、换世界、同场好友和涉及朋友圈的合并时间线；原始事件放进按需展开的证据层。
2. ⬜ **交汇变化摘要**：比较近 24 小时、7 天与 30 天，提示“新出现的圈层交汇、明显升温或暂时沉寂”，并展示样本量，覆盖不足时不下结论。
3. ⬜ **共同移动链**：识别短时间内多位好友从同一世界迁移到另一世界的观测序列；只描述共同变化，不推断谁邀请或带领了谁。
4. ⬜ **每日社交简报**：每天最多 5 条值得看的场景，优先跨圈、多好友同场和久未出现者回归，替代无限事件流。
5. ⬜ **覆盖度地图**：按好友展示最近观测时间、可见位置比例和关系扫描状态，明确哪些结论数据充分、哪些只是暂时没有记录。

参考 VRCX 的好友日志持久化方式后，VRC++ 继续保留可追溯的底层事件，但原创产品层以“场景聚合 + 关系解释 + 覆盖度”作为主体验，不复制原始日志列表。

后续可用性顺序：

1. 逐页补齐好友详情、世界详情、群组、头像和系统中心的英文文案；

4. 将资料保存拆成“状态”和“简介”两个独立提交区，降低上游第二步失败时的部分成功理解成本。

## 2026-08-15 下一阶段功能池

> 目标：把“发现人或世界 → 查看资料 → 形成本机记录 → 执行一次明确操作”串成日常使用闭环。不以扩大扫描量代替产品价值。

1. **P0 今日动态首页**（可直接实现）：汇总可加入好友、朋友所在世界、待处理请求、关注世界变化和网络状态；只做信息密度高的工具首页，不做营销式仪表盘。
2. **P0 好友档案 2.0**（本机推导）：增加共同会话时长、常遇世界、最近同场、活跃时段、关系时间线和数据覆盖度；所有结论标注“基于本机观测”。
3. **P0 发现中心与单人加好友**（可直接实现）：整合精确用户搜索、公共实例成员、群组成员和本机日志中已知用户；查询好友状态后，仅在用户二次确认时发送单个好友请求，不提供批量添加。
4. **P0 相交朋友圈演变**（本机推导）：增加跨圈关键好友、两个朋友圈对比、主题好友更换记录、新增/消失的已观察连线与时间滑块；“未观察到”不等于“好友关系消失”。
5. **P1 群组中心**（受会员资格和权限限制）：展示已加入群组、公告/帖子、活跃群组实例和可加入状态；成员和管理数据按上游权限显示，不尝试绕过 403。
6. **P1 世界回忆与本机推荐**（本机推导）：按到访次数、最近到访、同行好友和收藏变化生成世界回忆；推荐只使用本地历史与已可见数据，无需上传好友关系。
7. **P1 头像收藏柜**（仅当前账号）：查看自己的 VRChat 上游头像收藏，支持本机标签、兼容平台、性能等级和最近使用整理；不读取他人私有头像，不下载 AssetBundle。
8. **P1 国内线路与缓存控制台**（可直接实现）：请求延迟、缓存命中、403/429、Pipeline 重连、图片 CDN 状态、LRU/容量上限与脱敏诊断包。

明确不规划“查看任意用户完整好友列表”：上游只能稳定提供当前账号的好友列表和与指定用户的共同好友，因此“某人的好友但你还不认识”不能作为可验收的数据来源。
