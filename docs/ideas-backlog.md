# 产品点子与待办池

这里记录值得保留但不一定马上实现的点子。状态使用：`NOW`、`NEXT`、`LATER`、`HOLD`。

> 实现批注（2026-08-13）：本文件的 `NOW/NEXT/LATER/HOLD` 表示产品优先级，不表示已经完成。离线优先好友面板、世界搜索和 Pipeline/SSE 已有首版底座；所有产品功能的真实实现状态统一以 [实现状态批注](implementation-status.md) 为准。

具体迭代顺序、验收条件和模块依赖见 [功能完善路线](feature-roadmap.md)。

## 1. 高价值、低风险

### NOW：离线优先好友面板

> 🟡 已实现增强版：实时/快照来源、短 TTL SQLite 快照、上游失败回退、可点击好友资料、位置/世界解析、共同好友和 VRChat 备注；下一步补本地备注/标签、分组和精细增量事件。

先显示最后一次好友快照，再异步刷新；顶部明确标识“实时 / 延迟 / 离线缓存”。中国线路波动时，这会比空白加载页好很多。

依赖：好友快照、Pipeline、缓存时间戳。

### NOW：统一搜索框

支持粘贴用户 ID、世界 ID、群组 ID、VRChat URL、实例 location；普通文本再按类型搜索。结果显示来源和更新时间。

依赖：ID/URL parser、搜索节流。

### NOW：网络诊断中心

分别检测：

- VRChat REST；
- Pipeline WebSocket；
- 图片 CDN；
- DNS/TLS/系统时间；
- 本地日志路径；
- 当前是否启用代理；
- Cookie 是否存在但不展示值。

输出一份自动脱敏的诊断包，用户可以直接发给开发者。

### NOW：本地备注与标签

给好友、世界、头像加自己的备注、标签和颜色。它不依赖上游字段，价值高且不增加 API 风险。

### NEXT：重逢提醒

当很久没见的好友上线或进入同一实例时提醒。规则完全在本地计算：例如 30 天未共同出现、累计共同在线超过 5 小时。

注意：默认关闭敏感位置提醒，只展示“已上线”或“可能遇见”。

### NEXT：活动热力图

以“星期 × 小时”展示好友活动规律，并提供数据覆盖天数。数据不足时不输出看似精确的结论。

### NEXT：世界回忆卡片

把本地截图、首次访问、总停留、遇到的好友和个人备注聚合到世界页面。缩略图只在本地生成。

### NEXT：一键加入与复制安全链接

从世界/实例页生成 VRChat 官方网站链接或本机启动动作。复制私密实例链接前警告其中可能包含访问 nonce。

## 2. 国内体验差异化

### NEXT：双更新源

国内对象存储为主、GitHub Releases 为备；二者使用同一签名 manifest。更新失败不影响当前版本使用。

### NEXT：图片本地缓存

> 🟡 已实现首版：VRChat 域名白名单、本机同源读取、16 MiB 上限、栅格格式限制和磁盘复用；下一步实现磁盘 LRU、容量设置、失败占位图与手动清理。

磁盘 LRU、尺寸分级、失败占位图、手动清理。不要做中心化的全站图片镜像。

### NEXT：代理配置档案

> 🟡 已实现单配置首版：跟随系统、直连、本机 HTTP/SOCKS5，并统一作用于 REST、Pipeline、图片。下一步支持多个命名档案和一键对比检测。

支持跟随系统、直连、自定义 HTTP/SOCKS 三种模式；保存的是地址配置，不保存公共代理列表。切换时显示出口 IP 变化可能导致重新验证。

### LATER：局域网手机遥控

电脑网关显示二维码，手机在同一局域网打开控制页。设备间做短码配对和 E2E 会话，默认只读；邀请、删好友等写操作仍需电脑确认。

### LATER：远程只读模式

电脑在线时，手机通过云端密文中继读取在线好友和通知摘要。云端不知道 VRChat Cookie，也不能自行调用 VRChat。

## 3. 社交与数据洞察

### NEXT：好友关系时间线

记录成为好友、改名、上线、共同世界和备注变更。展示“本地观测到”，不要包装成 VRChat 官方事实。

### NEXT：常遇好友

按共同实例会话去重统计，而不是按日志行数统计。推荐主指标：过去 30 天共同出现的不同会话数；补充总时长和不同世界数。

### NOW：社交圈图谱

> 🟡 已实现增强首版：仅基于自己能看到的共同好友结果生成本地图谱，按需每批扫描 20 位，支持停止、覆盖率、搜索、在线/孤立点筛选、邻居高亮、真实头像、画布缩放/平移、节点拖动、头像碰撞避让和好友详情跳转。下一步做大图虚拟化、拖动布局持久化、圈层命名和按扫描时间刷新。

边界：连线表示“至少一次查询确认”；缺边可能是未扫描、接口截断、网络失败或对方未共享，不能据此推断双方不是好友。原始关系和布局默认不上传、不公开，403/404 只记录为“未共享/不可用”。

### LATER：世界发现推荐

根据用户自己的访问、收藏、停留和标签推荐世界，不做大规模全站爬虫。解释推荐原因，例如“你收藏的 3 个摄影世界作者也发布了它”。

### LATER：活动日记

每天自动生成本地摘要：去了几个世界、遇见几位好友、保存了哪些截图。用户确认后才能导出分享。

## 4. 创作者辅助

### NEXT：世界收藏与更新提醒

比较已收藏世界的 `updatedAt`，提示有更新；使用长 TTL 和分散刷新，不能同时扫描全部世界。

### LATER：实例组织面板

创建实例参数向导、邀请清单、活动开始倒计时。所有写操作明确展示将调用什么，禁止一键群发大量邀请。

### LATER：群组活动日历

读取可见的群组/日历事件，生成本地 ICS 订阅或提醒。先做只读，发布和管理功能后置。

## 5. 安全与可维护性

### NOW：上游兼容开关

每个高风险或易变模块都有独立 feature flag：登录、Pipeline、通知 V2、群组、头像详情等。上游变化时可关掉一个模块而不是让整个应用不可用。

### NOW：脱敏日志查看器

用户导出前可以预览将发送的内容；Cookie、Authorization、token、邮箱、私密 instance nonce 强制替换为占位符。

### NEXT：本地数据保险箱

一键导出备注、标签、布局和历史的加密备份；会话 Cookie 默认永不进入备份。

### NEXT：API 行为仪表盘

只在本机统计最近 24 小时请求数、缓存命中率、429、403、平均延迟和 Pipeline 重连次数。它既方便优化，也能及时发现异常循环。

### LATER：兼容性众测

用户可选择上传不含实体内容的兼容指标，例如端点状态码、响应 schema 指纹、版本和区域。任何原始用户/好友/世界 JSON 都不上传。

## 6. 暂缓或不建议

### HOLD：纯云端代登录

开发简单，但共享出口、集中 Cookie、集中限流和连坐风险太高。除非未来 VRChat 提供 OAuth 或书面授权，否则不作为正式架构。

### HOLD：公共世界/用户全量镜像

会产生持续扫描、数据过期和隐私问题，也不符合小工具的必要范围。改用按需缓存和用户自己的历史。

### HOLD：自动值守账号

自动接受好友、自动邀请、自动群组管理很容易从“辅助工具”变成 bot。第一版所有改变上游状态的行为都必须由用户点击。

### HOLD：头像资产下载/分析

与这个伴侣应用的核心价值无关，风险和争议远高于收益。只处理 API 返回的、用户有权查看的元数据与图片。

### HOLD：公共代理池和自动换 IP

出口频繁变化本身会提高登录风控，也可能把正常用户和被滥用的 IP 绑定在一起。仅提供用户自有代理配置。

## 7. 产品命名想法

避免使用容易让人误认为官方的 “VRChat China / VRChat CN”。可以考虑：

- VRC++（正式产品名）；
- VRC Lantern（灯笼，中文社区辨识度）；
- VRC Compass（罗盘，世界发现）；
- VRC Nest（个人本地数据中心）；
- 星门伴侣 / 世界罗盘（中文产品名）。

最终名称需要检查域名、GitHub、商标和应用商店冲突，并在 About 页标注非 VRChat 官方产品。

## 8. 第三阶段原创功能方向（2026-08-15）

> 参考 VRCX 2026 年 README 与近期发布后，不再把“多做几个列表、日历或仪表盘”当作差异化。VRCX 已覆盖好友/世界/头像/群组管理、活动热力图、通知、GameLog、Group Calendar、Dashboard、状态预设和导入导出。VRC++ 的原创主线改为：本机推导、行动建议、国内网络韧性。

### P0：今晚罗盘

把当前可加入好友、好友聚集世界、相交朋友圈、群组活动、世界收藏和线路状态组合成 3 条“今晚可以做什么”的候选路线：

- 去哪：推荐一个当前可进入或适合稍后进入的世界；
- 找谁：展示候选好友及与自己的本机观测依据；
- 为什么：例如“3 位常遇好友在同一公开实例”“这个朋友圈今晚有 5 人在线”；
- 阻碍：实例满员、私人实例、线路异常、数据过期必须明确显示。

首版采用可解释规则评分，不接云端大模型，不自动加入实例或发送邀请。用户点开候选后仍进入现有世界/好友详情逐项操作。

### P0：本机社交查询

提供中文自然语言式查询，但首版使用本地意图解析器和固定查询模板，不把好友数据上传给 AI：

- “周五晚上经常遇见谁”；
- “30 天没见但现在在线的好友”；
- “同时连接摄影圈和中文圈的人”；
- “我和 A 最常在哪些世界同场”；
- “哪些结论数据覆盖不足”。

每条结果必须携带数据来源、覆盖天数和可复核入口。无法回答时返回缺少哪些观测，不生成猜测。

### P0：重逢雷达

使用本机共同会话、最近同场、累计相遇次数和当前在线状态，发现“值得重新打招呼”的好友。提醒理由必须可解释，默认只提示上线，不公开私人位置。用户可为单个好友设置冷却、忽略或“保持联系”目标。

### P1：社交潮汐

把各相交朋友圈的本机在线观测按星期和小时聚合，显示“哪些圈通常在什么时候活跃”和两个圈层的活跃交集。它用于安排时间，不预测个人精确上线时间。覆盖不足的时间段显示为空，不做平滑造数。

### P1：世界护照

将世界访问、同行好友、首次/最近到访、停留区间、收藏变化、本机备注和用户主动关联的截图组成可回看的“旅程”。与 VRCX 的截图世界元数据不同，重点是跨世界的旅程线和社交上下文。截图必须由用户选择目录或手动关联，默认不扫描整个图片库。

### P1：好友动向与朋友圈交汇

把零散状态变化合并成“同一时间、同一世界、哪些朋友圈正在交汇”的场景。实时状态按可见 instance 聚合，历史按时间窗口与世界聚合；每个场景给出参与好友、朋友圈数量、跨圈连线与关键连接人。私人位置和缺失观测只显示未知，不推断轨迹。

### P1：中国线路起航检查

在用户准备参加活动前低频检查 REST、Pipeline、图片缓存和目标世界资料是否可用，提前缓存封面与公开元数据，并给出“可正常使用 / 建议切换本机代理档案 / 仅离线快照可用”。不测试公共代理，不自动更换出口 IP。

### 原创性验收

- 不是把已有列表换一种卡片样式；
- 至少融合三个现有本机数据源；
- 每个推导能说明依据、时间和缺失数据；
- 断网时仍能展示上次结果并明确过期；
- 所有 VRChat 写操作继续由用户逐项确认。

## 9. 第四期落地批注（2026-08-15）

- ✅ 社交潮汐第一版：关系圈、历史事件、本机时区三类数据已融合；孤立点默认不进入统计。
- ✅ 世界护照第一版：到访时间线、同行者和本机批注已形成闭环；截图只接受后续用户主动选择，不增加自动目录扫描。
- ✅ 好友动向第一版：已替换活动编队；位置与事件先聚合再展示，并叠加朋友圈交汇和连接人分析。
- ✅ 起航检查第一版：REST、Pipeline、数据库、线路模式、媒体缓存与世界线索分层展示；不会自动换出口。

下一步优先做两项增强：一是为场景增加按好友/朋友圈/世界回放的筛选器，二是把“圈层突然交汇、熟悉好友换圈活跃”做成本机摘要。目标世界预热仍只缓存公开元数据和封面，并由用户点击触发。
